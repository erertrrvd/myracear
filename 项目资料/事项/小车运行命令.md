# 本车雷达建图运行命令

在小车车载机 `root@192.168.5.100` 的 SSH 终端运行。车载 ROS 2 Humble 工作空间为 `/home/racecar`。两个长期运行的终端都要保持打开。此流程使用独立建图入口，不启动固定路线行驶控制。

## 日常启动

窗口一：先启动本车硬件驱动，保持运行。`Run_car.sh` 已启动雷达、IMU、编码器和车体到雷达的静态 TF，不必再单独启动 `lslidar_driver`。

```bash
cd /home/racecar
source /opt/ros/humble/setup.bash
source /home/racecar/install/local_setup.bash
bash Run_car.sh
```

窗口二：在窗口一仍运行时启动建图。

```bash
cd /home/racecar
source /opt/ros/humble/setup.bash
source /home/racecar/install/local_setup.bash
ros2 launch my_racecar mapping_only.launch.py publish_laser_tf:=false ready_timeout:=180
```

`publish_laser_tf:=false` 必须与本车当前 `Run_car.sh` 配套：驱动入口已经发布 `base_footprint → base_link → laser_link`，建图入口不能再为同一个 `laser_link` 发布另一条静态 TF。车载现有 TF 合成的雷达平移约为前方 `0.07 m`、高度 `0.15 m`，尚未经尺量。此运行方式不会使用独立建图入口默认的 `z=0.30 m` 目测外参。`ready_timeout:=180` 为排查留出时间；入口默认 60 秒。

当前 `/scan.header.frame_id` 已查到是 `laser_link`。建图入口只会启动融合里程计、TF 适配、日志、SLAM Toolbox 和就绪检查；它不会自动驾驶。保持窗口二运行，让车辆缓慢移动时，地图应随扫描更新。不要同时启动旧的固定路线、导航或其他 SLAM 入口。

## 同步检查与保存

窗口三：在建图仍运行时检查。话题出现在 `ros2 topic list` 中不等于有发布者。

```bash
source /opt/ros/humble/setup.bash
source /home/racecar/install/local_setup.bash
ros2 topic info /scan -v
ros2 topic info /map -v
timeout 8s ros2 topic echo /scan --once --qos-reliability best_effort
tail -n 3 /home/racecar/maps/mapping_only/.run1-live.jsonl
```

应确认 `/scan` 有发布者且能收到 `laser_link` 的新扫描，统计中的 `scans` 持续增加，`/map` 由本次 SLAM 发布且地图更新。还应在 RViz 检查 `map → odom → base_footprint → base_link → laser_link`、墙面连续性及转弯时是否重影。用户已反馈“现在可以运行了”；本对话尚无最终地图文件或 RViz 精度验收输出。

建图质量确认后，保持前两个窗口运行，在窗口三保存：

```bash
ros2 run my_racecar save_mapping --run-index 1 --map-dir /home/racecar/maps/mapping_only
ls -l /home/racecar/maps/mapping_only/run1/
```

核对 `complete.json`、`map.posegraph`、`map.data`、`map.pgm`、`map.yaml` 后再停止建图。若 `run1` 已存在，入口会拒绝覆盖；下一次试验给启动命令加 `map_dir:=/home/racecar/maps/mapping_only_02`，保存命令也使用相同目录。

## 首次部署或代码更新后

只有车载源码发生更新时才需要重新编译；日常启动不用每次执行 Git 或 `colcon build`。

```bash
cd /home/racecar
source /opt/ros/humble/setup.bash
colcon build --packages-select my_racecar --symlink-install
source /home/racecar/install/local_setup.bash
```

当前 `mapping_only.launch.py` 仍依赖编码器与 IMU 融合出的 `/encoder_imu_odom`，再由 `odom_tf_adapter` 发布 `odom → base_footprint`；它不是完全不使用编码器和 IMU 的纯雷达里程计方案。详细记录见同目录《小车雷达话题和发布接入项目slam的过程以及以后的提醒映射到其他小车.md》。

## 新增：电脑 CPU 建图，车端继续行驶

这是另一种**独立模式**，不要与上面的车端 `mapping_only.launch.py` 或旧 `race_mapping.launch.py` 同时运行。车上保留原硬件驱动和固定路径控制，仅增开里程计 TF；电脑运行 SLAM Toolbox，并把最终地图保存到 `D:\ubuntu\slam\maps`。电脑端 ROS 2 与 SLAM Toolbox 已安装并完成本机启动检查；**尚未部署到车上，也未完成跨机实测，不能把下面命令说成已实车跑通**。ROS 2 不用 ROS 1 的主从机设置；完整条件见 C 盘工作副本的 `mapping/DISTRIBUTED.md`。

车端在原硬件和行驶入口运行后，另开 SSH 窗口。原行驶入口若已启动 `imu_encoder_mix`，保持 `start_odom:=false`：

```bash
cd /home/racecar
source /opt/ros/humble/setup.bash
source /home/racecar/install/local_setup.bash
ros2 launch my_racecar distributed_mapping_vehicle.launch.py start_odom:=false
```

电脑端优先使用 **Windows 原生 Pixi 环境**。先联网安装；切换到小车局域网后再启动 SLAM。Pixi 环境和缓存位于 `D:\ubuntu\slam`：

```powershell
$pixi = "$env:LOCALAPPDATA\pixi\bin\pixi.exe"
$manifest = 'D:\ubuntu\slam\pixi.toml'
$env:PIXI_CACHE_DIR = 'D:\ubuntu\slam\cache'
& $pixi install --manifest-path $manifest
$env:ROS_DOMAIN_ID = '0'
$env:ROS_LOCALHOST_ONLY = '0'
& $pixi run --manifest-path $manifest ros2 launch 'C:\Users\lzc2\Desktop\my_racecar（复件）\launch\distributed_mapping_pc.launch.py' map_dir:=D:/ubuntu/slam/maps
```

完成建图并保持电脑端 SLAM 运行时，另开 PowerShell 窗口保存：

```powershell
$pixi = "$env:LOCALAPPDATA\pixi\bin\pixi.exe"
$manifest = 'D:\ubuntu\slam\pixi.toml'
$env:PIXI_CACHE_DIR = 'D:\ubuntu\slam\cache'
$env:ROS_DOMAIN_ID = '0'
$env:ROS_LOCALHOST_ONLY = '0'
& $pixi run --manifest-path $manifest python 'C:\Users\lzc2\Desktop\my_racecar（复件）\mapping\scripts\save_mapping' --run-index 1 --map-dir D:/ubuntu/slam/maps
```

电脑端另开 PowerShell 窗口可启动 RViz（已安装到同一 Pixi 环境）：

```powershell
$pixi = "$env:LOCALAPPDATA\pixi\bin\pixi.exe"
$manifest = 'D:\ubuntu\slam\pixi.toml'
$env:PIXI_CACHE_DIR = 'D:\ubuntu\slam\cache'
$env:ROS_DOMAIN_ID = '0'
$env:ROS_LOCALHOST_ONLY = '0'
& $pixi run --manifest-path $manifest rviz2
```

RViz 中 Fixed Frame 选 `map`，添加 `/map` 的 Map、`/scan` 的 LaserScan 和 TF。雷达不显示时检查 LaserScan 的 QoS Reliability 是否为 Best Effort。RViz 本机可执行文件已确认；显示实车地图仍需小车跨机通信验证。

以下 **WSL Ubuntu 22.04** 命令仅是备用方式，需先安装 ROS 2 Humble、SLAM Toolbox 并验证跨机 DDS 通信：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=0
export ROS_LOCALHOST_ONLY=0
ros2 launch '/mnt/c/Users/lzc2/Desktop/my_racecar（复件）/launch/distributed_mapping_pc.launch.py' \
  map_dir:=/mnt/d/ubuntu/slam/maps
```

`ROS_DOMAIN_ID=0` 是示例，要与车端实际值一致。地图确认可用、电脑 SLAM 仍运行时，在电脑 WSL 内保存：

```bash
/usr/bin/python3 '/mnt/c/Users/lzc2/Desktop/my_racecar（复件）/mapping/scripts/save_mapping' \
  --run-index 1 --map-dir /mnt/d/ubuntu/slam/maps
```

这三步不会让电脑发送车辆运动指令。电脑掉线会中断建图，不会由新建图入口关闭车上的独立行驶流程。
