## 1. 先看旧功能：路线怎样录制和跟踪

### 1.1 录制路线

按下列顺序读：

1. [launch/save_path.launch.py](<my_racecar（复件）/launch/save_path.launch.py>)：看它启动 `get_distance`、外部包 `encoder_imu` 的 `imu_encoder_mix`、`save_path`。`encoder_imu` 源码不在本包内。
2. [src/get_distance.cpp](<my_racecar（复件）/src/get_distance.cpp>)：从 `/encoder` 的线速度积分出累计路程 `/distance`，没有读取融合里程计；注意时间差和异常时间处理。
3. [src/save_path.cpp](<my_racecar（复件）/src/save_path.cpp>)：从 `/encoder_imu_odom` 更新 x/y/yaw，它们表示 `base_footprint` 在 `odom` 中的平面位姿，yaw 单位为弧度；设计上是本次里程计起点后的相对位姿，但 `imu_encoder_mix.cpp` 首次积分前未初始化 `last_time`，首帧速度非零时 x/y 可能异常，不能直接认定起点是 `(0,0)`。收到 `/distance` 且比上次存点多至少 `save_dx` 时，写 `path.csv` 并发布 Marker。Marker 当前标为 `map` 帧，却直接使用 `odom` 数值，没有坐标变换。另一路 `/scan` 回调将本次运行中首帧成功写入的扫描保存到 `init_scan.csv`；它过滤无效距离，但没有要求最少有效点数。

### 1.2 读取并执行旧路线

4. [launch/move_test.launch.py](<my_racecar（复件）/launch/move_test.launch.py>)：旧路线的主要入口。记录 `get_local_path` 和 `pure_track_test` 的参数，尤其 `stop_point`、`slow_point`、`start_icp`、速度和停车点索引。`start_odom` 默认启动融合里程计；组合建图入口会把它设为 `false`，避免重复启动。
5. [src/get_local_path.cpp](<my_racecar（复件）/src/get_local_path.cpp>)：先读 `CSV_get_Path` 如何装入路径，再找订阅 `/encoder_imu_odom`、提取当前位置附近路径、起点扫描匹配、发布 `/my_local_path` 和 `/my_global_path`。节点不要求车在数学原点才启动，但旧路线跟踪依赖本次里程计与录制路线的起点和方向对齐；`start_icp=1` 只尝试局部起点扫描校正，ICP 尚未成功时源码也会继续发布局部路径。`pub_global_path=0` 只关闭全局路径显示，不能仅凭 RViz 没有全局路径就判断 CSV 没读到；具体起跑限制见上一级 `事项.md` 的 2026-09-27 说明。
6. [src/pure_track_test.cpp](<my_racecar（复件）/src/pure_track_test.cpp>)：从 `/my_local_path` 回调读到预瞄、横向/航向误差、速度模式、红绿灯与停车状态，最后找到 `/cmd_vel` 发布。重点核对 `v_mode`、`first_stop_index`、`second_stop_index` 与路径点索引的关系。
7. [src/transform_v.cpp](<my_racecar（复件）/src/transform_v.cpp>)：单独看 `/cmd_vel` 与 `/encoder` 速度反馈如何转成 `car_cmd_vel`。这一步与底盘驱动接口有关，不能把 `/cmd_vel.angular.z` 的数值直接理解成已经施加到前轮的角度。**`move_test.launch.py` 没有启动这个节点**；在车上须查实际由哪个进程完成控制命令转换。

把代码涉及的数据链画成一句话：`编码器/IMU → /encoder_imu_odom`；`path.csv + /encoder_imu_odom → get_local_path → /my_local_path → pure_track_test → /cmd_vel`；若单独运行 `transform_v`，它再把 `/cmd_vel` 转为 `car_cmd_vel`。其中 `path.csv` 是预存路线，旧流程不能因此称为实时 SLAM 导航。

### 1.3 旧路线的其他入口

- [launch/move_new.launch.py](<my_racecar（复件）/launch/move_new.launch.py>)：与 `move_test` 对照节点和参数。它另启动订阅 `/map` 并写 `map.csv` 的 `map_recieve_node`，却不启动 `imu_encoder_mix`；`light_mode=0` 仅有“基于 yolo”注释，当前 `pure_track_test.cpp` 未读取该参数，本包也未启动 YOLO 检测节点。当前 `race_mapping.launch.py` 明确包含的是 `move_test`，详情见上一级 `事项.md` 的 2026-09-27 对比。
- [launch/final_start.launch.py](<my_racecar（复件）/launch/final_start.launch.py>)：读多套比赛参数与实际选用的启动节点；参数表不是实时调参结果。
- [launch/car_move.launch.py](<my_racecar（复件）/launch/car_move.launch.py>)、[src/move_control.cpp](<my_racecar（复件）/src/move_control.cpp>)、[src/move_control_test.cpp](<my_racecar（复件）/src/move_control_test.cpp>)：了解早期按标志位运动的控制分支，不要与 `pure_track_test` 同时向同一控制话题发命令。

## 2. 再看新增功能：三趟建图怎样串接旧路线

先完整读 [mapping/README.md](<my_racecar（复件）/mapping/README.md>)，再按执行顺序看：

1. [mapping/launch/race_mapping.launch.py](<my_racecar（复件）/mapping/launch/race_mapping.launch.py>)：检查三趟编号、上一趟地图校验、启动 SLAM Toolbox、等待建图就绪、最后包含 `move_test.launch.py` 的条件。这里决定了旧路线何时放行。
2. [mapping/config/mapper.yaml](<my_racecar（复件）/mapping/config/mapper.yaml>)：核对扫描话题、坐标系、更新频率和匹配参数；参数仍需按实车雷达与算力标定。
3. [mapping/scripts/odom_tf_adapter](<my_racecar（复件）/mapping/scripts/odom_tf_adapter>)：看旧里程计如何转为建图需要的 TF；重点查 `map`、`odom`、`base_footprint`、`laser_link` 是否形成唯一且连续的链。
4. [mapping/scripts/mapping_ready](<my_racecar（复件）/mapping/scripts/mapping_ready>)：看扫描、里程计、TF、地图和起点匹配各自如何判定就绪。地图文件已加载不代表位置已经收敛。
5. [mapping/scripts/mapping_status_logger](<my_racecar（复件）/mapping/scripts/mapping_status_logger>)：看每趟记录哪些话题和地图状态。
6. [mapping/scripts/save_mapping](<my_racecar（复件）/mapping/scripts/save_mapping>)：看地图与位姿图的保存、完整性检查、`complete.json`。按 README 的操作，车停稳后再保存。
7. [mapping/rviz/slam_mapping.rviz](<my_racecar（复件）/mapping/rviz/slam_mapping.rviz>)：看已配置的 Map、LaserScan、TF 等显示项。它只是查看工具，不参与控制。

当前建图入口沿用旧 `path.csv` 和旧控制器；它增加的是 SLAM Toolbox 建图与存图链，**不是**“建图后由 Nav2 自主规划路线”。判断比赛要求是否满足，应分别检查真实地图、起点定位、实际行驶控制来源。不要同时单独启动 `move_test.launch.py` 和 `race_mapping.launch.py`。

## 4. 阅读后用源码和实车各核对一次

1. 在源码中确认实际启动入口、每个入口启动的节点，以及是否有两个节点同时发布 `/cmd_vel`。
2. 核对 `path.csv` 的点数、坐标和停车点索引；代码里的硬编码车载路径要与车上文件位置一致。
3. 上车后再查 `/scan` 时间戳、`header.frame_id`、TF、`/encoder_imu_odom`、`/map`、`/my_local_path` 和 `/cmd_vel`。源码存在某个发布器，不等于现场该话题正常。
4. 若要看实时建图，按 `mapping/README.md` 的网络与 RViz 步骤操作；三趟是否完整保存以各趟 `complete.json` 及地图文件校验为准。
