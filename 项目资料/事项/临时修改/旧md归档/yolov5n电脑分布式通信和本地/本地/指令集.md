# 本地识别（小车自己跑）：指令集

小车用昇腾 NPU 跑 `.om` 模型，识别在小车上完成：`light_infer.py`（root 的 conda `python3`，装有 ais_bench）把结果写到状态文件，`light_bridge.py`（ROS 的 `/usr/bin/python3`）读文件并发布话题。两个进程分开，是因为 ais_bench（Python 3.9）和 rclpy（Python 3.10）不能放在同一个进程里。

> **重要**：本文件夹是**电脑项目里的版本**。小车上的 `light_bridge.py`、`start_vision.sh` 有未提交的改动，并且多了 `light_infer_daemon.py`，**还没有同步到电脑**，所以小车上实际的行为可能和这里不同，以小车上的文件为准。同步方法见 `..\..\git和小车修改冲突解决方法\指令集.md` 第 7 节。

## 0. 前提

- 模型文件 `camera_capture/output/yolov5n_bs1.om` 要存在（不进 git，需要 `scp` 或在小车上转换）。
- 先停掉远程识别（`start_remote_vision.sh`），摄像头同一时间只能开一套。
- 以下都在小车上，用 root。

## 1. 检查环境和摄像头（只读）

```bash
cd /home/racecar/src/my_racecar/camera_capture && bash check_env.sh
```

```bash
cd /home/racecar/src/my_racecar/camera_capture && ls -lh output/yolov5n_bs1.om && fuser -v /dev/video0
```

`fuser` 没有输出表示摄像头空闲。

## 2. 一键启动：识别 + 发布话题

终端 1：

```bash
cd /home/racecar/src/my_racecar/camera_capture && bash start_vision.sh
```

- 后台启动 `light_infer.py`，等到第一帧结果，再前台启动 `light_bridge.py`。
- `Ctrl+C` 会同时停止两个。识别的日志在 `infer.log`。
- 启动前会检查：`.om` 是否存在、摄像头是否被占用、`light_infer.py` 是否已在运行。

带参数（会传给 `light_infer.py`）：

```bash
bash start_vision.sh --conf-box 0.4 --conf-lamp 0.4
```

终端 2，看话题：

```bash
source /opt/ros/humble/setup.bash && /usr/bin/python3 /home/racecar/src/my_racecar/camera_capture/light_listener.py
```

或者：

```bash
source /opt/ros/humble/setup.bash && ros2 topic echo /traffic_state
```

```bash
source /opt/ros/humble/setup.bash && ros2 topic hz /traffic_state
```

发布的话题（验证阶段，不影响运动）：

| 话题 | 类型 | 内容 |
|---|---|---|
| `/traffic_state` | `std_msgs/String` | `red` / `green` / `off` / `none` / `conflict` / `stale` |
| `/traffic_light_box` | `std_msgs/Float32MultiArray` | `[x1,y1,x2,y2,灯箱置信度,亮灯置信度,图宽,图高,结果延迟秒,推理fps]`，没灯箱时框为 -1 |

`/traffic_light`（`Int32`）在电脑项目的版本里是**关闭**的（标了 `[控制]`）。`stale` 表示状态文件超过 0.5 秒没更新，一律当作不能走。

## 3. 只调识别、不发话题

```bash
cd /home/racecar/src/my_racecar/camera_capture && bash run.sh
```

| 命令 | 作用 |
|---|---|
| `bash run.sh` | 终端打印状态（推荐先用这个） |
| `bash run.sh show` | 弹窗，需要 MobaXterm X server，很慢 |
| `bash run.sh video` | 录 30 秒带框视频到 `/tmp/out.mp4`，再 `scp` 回电脑看 |
| `bash run.sh images 文件夹` | 离线跑一个文件夹里的图片 |

可以在后面接参数，例如 `bash run.sh show --conf-box 0.4`。

## 4. 常用参数（`light_infer.py`）

| 参数 | 说明 |
|---|---|
| `--model` | `.om` 模型路径 |
| `--source` | 摄像头编号、视频或图片文件夹 |
| `--show` | 弹窗显示 |
| `--save-video` `--max-seconds` | 保存带框视频 |
| `--state-file` | 状态文件，默认 `/tmp/light_state.txt` |
| `--conf-box` `--conf-lamp` | 灯箱、亮灯的置信度阈值 |
| `--confirm` | 连续几帧一致才切换状态（默认 3） |

电脑项目里的版本还支持 `--ar-min/--ar-max`、`--cy-min/--cy-max`（几何过滤）和 `--no-filter`，具体以 `python3 light_infer.py --help` 为准。

## 5. 转换模型（只有换模型时才需要）

在小车上转换要约 2 小时，建议在 Linux 电脑上转换后再拷过去：见 `视觉模型` 里的转换说明和 `yolov5n11n.om训练过程\04_转om\`。

电脑把 onnx 拷到小车：

```powershell
scp "D:\VSCode\ros2技术集\智能车总文件\视觉模型\模型\yolov5n_best.onnx" root@192.168.5.100:/home/racecar/src/my_racecar/camera_capture/yolov5n.onnx
```

小车上转换：

```bash
cd /home/racecar/src/my_racecar/camera_capture && bash convert.sh
```

后台转换，用 `tail -f convert.log` 看进度；出现 `output/yolov5n_bs1.om` 说明完成。

## 6. 和运动代码的关系

- `pure_track_test` 现在会发布 `/traffic_light_req`，并订阅 `/traffic_light`。
- 电脑项目里的 `light_bridge.py` 不订阅 `/traffic_light_req`，也不发布 `/traffic_light`，所以用 `light_mode: 1` 跑时，小车会在 `traffic_light_index` 停车，等满 `traffic_light_time` 秒后放行，效果等同固定等待。
- 小车上的 `light_bridge.py` 如果已经改过，可能实现了按需启停和 `/traffic_light`，需要先同步到电脑才能确认。

## 7. 停止

终端 1 按 `Ctrl+C`。确认摄像头已释放：

```bash
fuser -v /dev/video0
```

没有输出即可。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| `找不到 output/yolov5n_bs1.om` | 先转换或 `scp` 模型文件 |
| `摄像头 /dev/video0 被别的程序占用` | 关掉占用的程序，包括远程识别 |
| `light_infer.py 已经在运行了` | `pgrep -f light_infer.py` 找到并停掉 |
| 识别进程启动后退出 | 看 `infer.log` 最后几行 |
| 话题没有数据 | 用 `/usr/bin/python3` 运行 ROS 部分，别用 conda 的 `python3` |
