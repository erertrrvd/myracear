# 小车和电脑 git 同步：完整指令集与冲突解决方法

适用：小车 `root@192.168.5.100`，仓库 `/home/racecar/src/my_racecar`；电脑仓库 `C:\Users\lzc2\Desktop\my_racecar（复件）`。
电脑上已经有名为 `car` 的 remote：`ssh://root@192.168.5.100/home/racecar/src/my_racecar`。

> 每条命令标了在哪里运行：**小车**（MobaXterm，bash）、**电脑 PowerShell**、**电脑 Git Bash**。
> 在错误的终端里运行会出错（`$env:USERPROFILE`、`xargs` 等只在对应的终端里有用），这是这次遇到的最常见的问题。

---

## 0. 原则

1. 先只读检查，再动手。
2. **不用 `--force`**。
3. 小车是**非裸仓库**，当前分支 `main` 不能被直接推送，所以电脑先推到小车的新分支 `from-pc`，再由小车合并。
4. 小车上没提交的改动，先提交或备份，再做任何合并，不要用 `git checkout -- 文件`、`git stash`、`git reset --hard` 去“清理”。
5. 合并只更新源码，**不会自动编译**，没有 `colcon build` 小车跑的还是旧程序。
6. 项目里有 GBK 编码的文件（例如 `src/pure_track_test.cpp`），不要用文本编辑器打开后重新保存；在终端里显示成 `▒` 或 `<B6>` 是显示问题，文件本身是好的。
7. 经过 git 时用补丁文件（`.patch`）拷贝，不要把终端里看到的内容复制粘贴当作文件内容。

## 2. 只读检查（随时可以运行，不改任何文件）

### 2.1 小车：看提交和未提交的改动

在**小车**：

```bash
cd /home/racecar/src/my_racecar && git log --oneline -5 && echo "--- 未提交（排除 camera_capture）" && git status --short -- . ':!camera_capture' && echo "--- camera_capture 的状态" && git status --short -- camera_capture
```

输出被分页器卡住（最后一行是 `:`）时，按 `q` 退出，以后命令统一加 `--no-pager`：

```bash
git --no-pager diff -- 文件路径
```

### 2.2 电脑：看和小车已提交内容的差异

在**电脑 PowerShell**（要输入小车密码，只下载提交，不改工作区）：

```powershell
cd "C:\Users\lzc2\Desktop\my_racecar（复件）"; git fetch car; git diff --stat main car/main -- . ':!camera_capture'
```

没有输出表示已提交内容一致。注意：这个命令**看不到**小车上未提交的改动，要靠 2.1 发现。

### 2.3 单个文件是否一致（哈希对比）

在**小车**：

```bash
cd /home/racecar/src/my_racecar && git hash-object launch/move_test.launch.py src/pure_track_test.cpp
```

在**电脑 PowerShell**：

```powershell
cd "C:\Users\lzc2\Desktop\my_racecar（复件）"; git hash-object launch/move_test.launch.py src/pure_track_test.cpp
```

两边都应是：

```
057679c06c54e69cfbfa4ca789481877287d1371
972535c7cf4a7c2b1de9ae748e87bad35d902758
```

### 2.4 整个项目是否一致（排除视觉文件）

在**小车**：

```bash
cd /home/racecar/src/my_racecar && git ls-files -z -- . ':!camera_capture' | xargs -0 git hash-object | sha256sum
```

在**电脑 Git Bash**（不能用 PowerShell，PowerShell 没有 `xargs`，会报 `could not open '?'`）：

```bash
cd "/c/Users/lzc2/Desktop/my_racecar（复件）" && git ls-files -z -- . ':!camera_capture' | xargs -0 git hash-object | sha256sum
```

两边前面那串十六进制相同，就说明除 `camera_capture` 外的项目文件一致。
这个对比只覆盖 git 跟踪的文件，不包括没被跟踪的新文件。

## 3. 把小车上的改动安全地取回电脑（补丁方式）

1. **小车**：生成补丁（只往 `/tmp` 写一个文件）：

```bash
cd /home/racecar/src/my_racecar && git --no-pager diff -- launch/move_test.launch.py src/pure_track_test.cpp > /tmp/car_local_changes.patch && ls -l /tmp/car_local_changes.patch
```

2. **电脑 PowerShell**：拷回（注意是在电脑上运行，不是在小车上）：

```powershell
scp root@192.168.5.100:/tmp/car_local_changes.patch "$env:USERPROFILE\Desktop\car_local_changes.patch"
```

3. **电脑 PowerShell**：先试运行，再应用：

```powershell
cd "C:\Users\lzc2\Desktop\my_racecar（复件）"
git apply --check "$env:USERPROFILE\Desktop\car_local_changes.patch"
git apply "$env:USERPROFILE\Desktop\car_local_changes.patch"
```

4. **电脑 Git Bash**：验证应用后与补丁逐字节一致（保证 GBK 没被破坏）：

```bash
cd "/c/Users/lzc2/Desktop/my_racecar（复件）" && git --no-pager diff -- launch/move_test.launch.py src/pure_track_test.cpp > /tmp/re.patch && cmp /tmp/re.patch "$USERPROFILE/Desktop/car_local_changes.patch" && echo IDENTICAL
```

看到 `IDENTICAL` 才算成功。

## 4. 标准同步流程（电脑和小车都有新提交时）

### 步骤 1：小车先把本地改动提交

在**小车**：

```bash
cd /home/racecar/src/my_racecar && git add 要提交的文件 && git commit -m "说明" && git log --oneline -2
```

如果提示没有设置身份：

```bash
git config user.name "你的名字" && git config user.email "你的邮箱"
```

### 步骤 2：电脑取回小车的提交并合并

如果电脑上有与小车**相同内容**但没提交的那几个文件，会挡住合并，先还原它们（内容已经在小车提交里，桌面还有补丁备份）：

在**电脑 PowerShell**：

```powershell
cd "C:\Users\lzc2\Desktop\my_racecar（复件）"
git restore launch/move_test.launch.py src/pure_track_test.cpp
git fetch car
git merge car/main --no-edit
```

### 步骤 3：电脑提交自己的新文件

在**电脑 PowerShell**（视觉文件示例）：

```powershell
git add camera_capture/remote_proto.py camera_capture/remote_vision_bridge.py camera_capture/pc_vision_client.py camera_capture/start_pc_vision.ps1 camera_capture/start_remote_vision.sh "camera_capture/README_远程视觉.md"
git commit -m "说明"
git status --short
```

`git status --short` 没有输出，表示工作区干净。

### 步骤 4：电脑推到小车的新分支

在**电脑 PowerShell**：

```powershell
git push car main:from-pc
```

这不改动小车的 `main` 和工作区。

### 步骤 5：小车快进合并

在**小车**：

```bash
cd /home/racecar/src/my_racecar && git status --short && git merge --ff-only from-pc && git log --oneline -4
```

`--ff-only`：不能快进（有分叉）或有冲突时直接拒绝，不会改动任何东西。

### 步骤 6：校验

按第 2.3、2.4 节对比。合并建图之后，2.4 里不再需要排除 `mapping`、`CMakeLists.txt`、`scripts/Run_car_safe.sh`。

## 5. 报错与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `error: The following untracked working tree files would be overwritten by merge` | 小车上有**未跟踪**的同名文件（手动拷上去的） | 先挪走再合并，不删除：`mkdir -p /root/pc_vision_backup && mv 那几个文件 /root/pc_vision_backup/`，然后 `git merge --ff-only from-pc`。这次就是这样处理的。 |
| `error: Your local changes to the following files would be overwritten by merge` | 小车上有**已跟踪文件**未提交的改动，且合并要改同一个文件 | 先在小车提交这些文件（步骤 1），或者用 `git diff > 文件.patch` 备份，再合并。不要用 `checkout --`、`stash`。 |
| `fatal: Not possible to fast-forward, aborting` | 两边都有新提交，分叉了 | 回到步骤 2：电脑先 `fetch car` 并 `merge car/main`，再推到 `from-pc`。 |
| `git push` 报 `refusing to update checked out branch` | 往小车当前分支（`main`）推送了 | 一律推到新分支：`git push car main:from-pc`。 |
| `Already : 无法将“Already”项识别为 cmdlet` | 把输出 `Already up to date.` 当命令粘进去了 | 只粘命令，不粘输出，没有影响。 |
| `can't open file '...\pc_vision_client.py'` | 在仓库根目录运行，文件在 `camera_capture\` | 先 `cd "...\my_racecar（复件）\camera_capture"`。 |
| `fatal: could not open '?' for reading` | 在 PowerShell 里运行了 `xargs` | 改用 Git Bash。 |
| `Permission denied, please try again.` | SSH 密码输错 | 重新输入；终端里输密码不会显示字符。 |
| 在小车终端里运行了 `scp ... "$env:USERPROFILE\..."` | `scp` 到电脑的命令必须在**电脑 PowerShell**里运行 | 检查有没有留下杂文件：`cd /home/racecar/src/my_racecar && git status --short; ls -la /root /home/racecar/src/my_racecar | grep -i userprofile`，有就贴出来确认后再删。 |
| 输出停在 `:` | 分页器 | 按 `q`；以后用 `git --no-pager ...`。 |
| 终端里中文注释是 `▒` / `<B6>` | GBK 编码，终端按 UTF-8 显示 | 只是显示问题；通过补丁和 `git` 传输，不要复制粘贴。 |
| 合并后小车行为没变 | 没有重新编译 | 要让 C++ 和 `CMakeLists.txt` 的改动生效，需要你自己决定是否 `colcon build`。 |

## 6. 回退（先备份，再动手）

合并前建议在**小车**先打一个标签：

```bash
cd /home/racecar/src/my_racecar && git tag before-sync-$(date +%Y%m%d) && git tag | tail -3
```

确需回到某个提交时，**先确认没有未提交的改动会丢**：`git reset --hard` 会丢掉所有已跟踪文件的未提交修改（例如 `light_bridge.py`、`start_vision.sh`）。先备份：

```bash
mkdir -p /root/backup_before_reset && cp camera_capture/light_bridge.py camera_capture/start_vision.sh camera_capture/light_infer_daemon.py /root/backup_before_reset/
```

然后才可以（回到小车自己的红绿灯提交 `02a512a`，即同步前的状态）：

```bash
git reset --hard 02a512a
```

这条是破坏性的，使用前先确认。已推到 `from-pc` 的分支不受影响。

## 8. 和 PC 远程视觉共存的注意事项

- 摄像头同一时间只能被一个程序占用：`start_vision.sh`（小车本地识别）和 `start_remote_vision.sh`（电脑识别）不能同时运行。
- `remote_vision_bridge.py` 默认只发验证话题 `/traffic_state`、`/traffic_light_box`，不影响运动；加 `--enable-control` 才会订阅 `/traffic_light_req` 并在请求期间发布 `/traffic_light`。
- 运动代码约定：`/traffic_light_req`（Int32）1 = 请求识别，0 = 关闭；`/traffic_light`（Int32）1 = 绿灯放行；`light_mode: 0` 为不依赖视觉的固定等待；等待超时（`traffic_light_time`）后无论如何放行。
- `traffic_light_index: 258` 要现场实测标定；`first_stop_index`、`second_stop_index` 现在也是 800，不想让它们停车就改成 999999。
- 第一次接入控制，建议先架空轮子试。
