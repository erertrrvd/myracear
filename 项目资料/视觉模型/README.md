## 2. 模型能识别什么

| 编号 | 类别 | 含义 |
|---|---|---|
| 0 | `light_box` | 整个红绿灯灯箱 |
| 1 | `red_on` | 亮着的红灯 |
| 2 | `green_on` | 亮着的绿灯 |

类别顺序不能改。没有橙灯类别，因为数据里没有橙灯亮的画面。

判断红绿的规则（脚本里已经实现）：

1. 灯箱框的长宽比要在 2.5 到 4.5，框中心高度在画面的 20% 到 85%，不满足的当作误检（椅子、人）。
2. 亮灯框的中心必须落在灯箱框里，才算“这个灯亮了”。
3. 灯箱里有亮红灯 → `red`；有亮绿灯 → `green`；红绿同时 → `conflict`；有灯箱没亮灯 → `off`；没有灯箱 → `none`。
4. 连续 3 帧一致才切换状态。
5. **只有 `green` 才算放行**，其余一律停车。

## 3. 怎么运行

下面的命令都在 PowerShell 里运行。先进入这个文件夹：

```bash
cd "D:\VSCode\ros2技术集\智能车总文件\视觉模型"
```

### 3.1 用电脑摄像头试模型（主要用这个）

```bash
D:\light_ai\venv\Scripts\python.exe 脚本\light_yolo11_cam.py
```

- 要用 `D:\light_ai\venv` 里的 Python，因为只有它装了 `ultralytics`（8.4.171）和 `torch`。**这个环境没有放进本文件夹，也不要删。**
- 第一次启动要等 1 到 2 分钟（导入 torch 比较慢），不要按 `Ctrl+C`。
- 窗口里先点一下画面，再按 `q` 退出。
- 画面左上角：`STATE` 是当前状态，下面是 `GO` 或 `STOP`。绿框是灯箱，红框是亮红灯，蓝橙框是亮绿灯。灰色框是被过滤掉或低于阈值的检测，旁边写着原因。

可以调的参数（加在命令后面）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--conf-box 0.5` | 0.5 | 灯箱置信度阈值 |
| `--conf-lamp 0.5` | 0.5 | 亮灯置信度阈值 |
| `--confirm 3` | 3 | 连续几帧一致才切换状态 |
| `--ar-min` `--ar-max` | 2.5 / 4.5 | 灯箱长宽比范围 |
| `--cy-min` `--cy-max` | 0.20 / 0.85 | 灯箱中心高度范围 |
| `--no-filter` | 关 | 关闭长宽比和高度过滤 |
| `--cam 0` | 0 | 摄像头编号，打不开时试 1 |
| `--model 路径` | 模型\yolo11n_best.pt | 换别的模型文件 |

例子：

```bash
D:\light_ai\venv\Scripts\python.exe 脚本\light_yolo11_cam.py --conf-box 0.3 --conf-lamp 0.4
```

### 3.2 只开摄像头看画面，不做识别

```bash

```

### 3.3 视频抽帧

```bash
python 脚本\extract_frames.py 数据\视频\某个视频.mp4 --every 5
```

- 图片默认存到 `数据\抽帧图片\视频名\`，每 5 帧取一张。
- `--out 文件夹` 指定保存位置，`--start 数字` 指定起始编号（接着上次的编号往后存，避免覆盖）。
- 这个脚本只需要系统 Python（装了 `opencv-python`），不需要 venv。

## 4. 训练情况

- 训练在另一台电脑上完成（有显卡），YOLO11n，100 轮，`imgsz=640`，`batch=16`。
- 数据：`数据集打包_给训练电脑用\light_dataset.zip`，训练 742 张、验证 344 张，**按整段视频划分**，验证的是完全没参与训练的 3 个视频（红灯、红变绿、绿灯）。
- 验证结果（第 86 轮最好）：精确率 0.999，召回率 1.000，mAP50 0.995，mAP50-95 0.927。
- 我另外用这 344 张验证图，按第 2 节的规则判断状态：红灯 172 张全部判 `red`，绿灯 172 张全部判 `green`，没有错的。

重新训练的命令（在训练电脑上，解压 zip 后进入 `light_dataset` 目录）：

```bash
pip install ultralytics
yolo detect train model=yolo11n.pt data=data.yaml epochs=100 imgsz=640 batch=16 patience=20
```

结果在 `runs\detect\train\weights\best.pt`。

## 5. 已知问题和局限

1. **数据太单一**：所有视频都是同一间教室、同一块灯箱，验证分数高不代表换环境也准。
2. **负样本很少**：整个数据集里只有约 6 张“画面里没有灯箱”的图，椅子、人、深色衣服被误检成灯箱的问题还没有解决。屏幕上的红色画面会不会被误判，也没有测过。
3. **没有“灯全灭”的数据**：几乎所有帧都有一个灯亮着，模型没学过三个灯都不亮时该输出什么。
4. **没有橙灯亮的数据**，所以不识别橙灯。
5. **标注是自动生成的**，抽查的框基本贴合，但没有逐张检查过 1086 张。
6. **笔记本摄像头和小车摄像头不一样**：训练图都是小车摄像头拍的，用笔记本摄像头测的结果不能代表小车上的效果。
7. **不能直接放到小车上**：这个 YOLO11 模型大概率不能直接转成小车用的 `.om`，课程的转换和推理脚本是按 YOLOv5 写的，我没有验证过 YOLO11 能否转换。正式上车要用 YOLOv5n 重新训练，数据可以直接用。
8. 画面里灯箱被切在边缘、只露出一部分的帧，标注时被剔除了，所以模型对“只看到半个灯箱”的情况没有数据。

## 6. 下一步建议

1. 用小车摄像头补拍：灯全灭、不同距离和角度、不同光线、室外，以及 100 到 200 张没有灯箱的画面（椅子、人、桌子、锥桶、屏幕）。
2. 补拍后重新标注、训练，并在小车摄像头上验证。
3. 确定上车方案：用 YOLOv5n 重训并转成 `.om`，或者验证 YOLO11 能否在小车的 CANN 7.0.RC1 上转换。
4. 把识别结果接进 `pure_track_test`：红灯停、绿灯走、其余不放行（见 `my_racecar（复件）\事项\红绿灯目标识别.md`）。
